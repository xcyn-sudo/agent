## 2. 系统总体设计

### 2.1 设计目标

| 目标 | 说明 |
|------|------|
| 高内聚低耦合 | 按业务领域划分模块，模块间通过接口和事件通信 |
| 可扩展 | LLM/Embedding 提供商可切换，向量数据库可替换，数据源类型可扩展 |
| 异步化 | 文档处理全链路异步，不阻塞用户操作；数据同步调度异步执行 |
| 安全性 | JWT 认证 + 角色授权 + BCrypt 密码加密 + 数据源凭据加密存储 |
| 可观测 | 关键操作日志记录，处理状态可追踪，数据质量可量化 |
| 多源融合 | 统一接入网关屏蔽异构数据源差异，ETL管道输出 Canonical 标准格式 |

### 2.3 核心设计模式

| 设计模式 | 应用场景 | 说明 |
|---------|---------|------|
| **策略模式** | LLM/Embedding 提供商切换 | 抽象 `LLMProvider` 和 `EmbeddingProvider` 接口，DeepSeek 和 Ollama 各自实现 |
| **CQRS** | 读写分离 | Command 处理写操作并发布事件，Query 只做查询 |
| **观察者模式** | 事件驱动处理链 | Spring Events 实现，各 Listener 监听事件异步处理 |
| **工厂模式** | LLM Provider 创建 | 根据配置创建对应的 Provider 实例 |
| **模板方法** | Prompt 构建 | 定义 Prompt 构建骨架，不同场景子类化 |
| **责任链+策略** | 混合检索 | 语义检索 + BM25 关键词检索双路召回 → 加权融合 → Rerank 精排 |
| **熔断器模式** | LLM 服务容错 | Ollama 连续失败自动熔断切换到 DeepSeek，半开探测恢复 |
| **补偿模式** | 数据一致性 | 文档删除先标记后清理 + 定时扫描孤儿向量，保证最终一致性 |
| **Connector 策略** | 多源数据接入 | DataSourceConnector 统一接口，JDBC/REST/S3 三种策略实现，支持全量和增量同步 |
| **规则链模式** | 数据质检 | 完整性→唯一性→格式→编码→长度顺序执行，任一维度异常记录到质检报告 |
| **管道模式** | ETL 标准化 | 分类→映射→转换→输出，每个阶段独立可替换，结构化数据转换为自然语言段落 |
| **生产者-消费者** | 批量向量化 | BlockingQueue 攒批 + 多消费者并发，单次 API 调用处理 32 条 |
| **路由模式** | CQRS 读写分离 | AbstractRoutingDataSource 根据 `@Transactional(readOnly)` 路由主库/从库 |
| **语义路由** | 知识目录匹配 | Embedding 向量相似度替代关键词匹配，query 与域描述向量做余弦相似度路由 |
| **属性访问控制** | ABAC 动态授权 | AbacEvaluator 综合用户属性（部门/密级/职级/域）和资源属性（域/密级）计算权限，SpEL 表达式注入 |

**接口定义**：

```java
/**
 * LLM 大语言模型策略接口
 * 通过实现此接口支持不同 LLM 提供商
 */
public interface LLMProvider {

    /**
     * 同步生成回答
     * @param messages 对话消息列表（含系统提示+历史+当前问题）
     * @return LLM 生成的回答文本
     */
    String generate(List<Message> messages);

    /**
     * 流式生成回答（可选实现）
     * @param messages 对话消息列表
     * @return 流式响应
     */
    Flux<String> generateStream(List<Message> messages);
}

/**
 * Embedding 嵌入模型策略接口
 * 通过实现此接口支持不同 Embedding 提供商
 */
public interface EmbeddingProvider {

    /**
     * 将单段文本转为向量
     * @param text 待向量化的文本
     * @return 浮点数向量数组
     */
    float[] embed(String text);

    /**
     * 批量文本向量化
     * @param texts 文本列表
     * @return 向量列表
     */
    List<float[]> embedBatch(List<String> texts);
}
```

**工厂类设计**：

```java
/**
 * LLM/Embedding Provider 工厂
 * 根据配置文件决定创建哪个实现
 */
@Component
public class ProviderFactory {

    @Value("${llm.provider:deepseek}")
    private String llmProviderType;

    @Value("${embedding.provider:deepseek}")
    private String embeddingProviderType;

    @Autowired(required = false)
    private DeepSeekLLMProvider deepSeekLLMProvider;

    @Autowired(required = false)
    private OllamaLLMProvider ollamaLLMProvider;

    /**
     * 根据配置获取 LLM Provider 实例
     */
    public LLMProvider getLLMProvider() {
        return switch (llmProviderType) {
            case "ollama" -> ollamaLLMProvider;
            default -> deepSeekLLMProvider; // 默认 deepseek
        };
    }

    /**
     * 根据配置获取 Embedding Provider 实例
     */
    public EmbeddingProvider getEmbeddingProvider() {
        return switch (embeddingProviderType) {
            case "ollama" -> ollamaEmbeddingProvider;
            default -> deepSeekEmbeddingProvider;
        };
    }
}
```

### 4.2 LLM 熔断降级设计 ★

当 Ollama 本地服务不可用时，系统通过熔断器自动降级：

```
                     ┌──────────────────────────┐
                     │    LLMCircuitBreaker      │
                     │  状态机：                  │
                     │  CLOSED → OPEN → HALF_OPEN│
                     └────────────┬─────────────┘
                                  │
              ┌───────────────────┼───────────────────┐
              │                   │                   │
              ▼                   ▼                   ▼
    ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
    │   CLOSED     │     │    OPEN      │     │  HALF_OPEN  │
    │ (正常状态)    │     │  (熔断状态)   │     │  (半开探测)  │
    │             │     │             │     │             │
    │ Ollama 处理  │ ──→ │ 自动切换至   │ ──→ │ 允许 1 个    │
    │ 连续失败 3 次 │     │ DeepSeek    │     │ 探测请求到   │
    │ → OPEN      │     │ 30s 后→     │     │ Ollama      │
    └─────────────┘     │ HALF_OPEN   │     └──────┬──────┘
                        └─────────────┘            │
                                          ┌────────┴────────┐
                                          │                 │
                                          ▼                 ▼
                                    成功 → CLOSED      失败 → OPEN
                                    (恢复正常)         (继续熔断)
```

**熔断配置参数**：
- 失败阈值：连续 3 次失败触发熔断
- 熔断时长：30 秒后进入半开状态
- 半开探测：允许 1 个请求探测 Ollama 是否恢复
- 降级链路：Ollama → DeepSeek API（自动切换，对用户透明）

### 7.2 JWT 双令牌设计

```
┌─────────────────────────────────────────────────────┐
│                 JWT 双令牌机制                        │
├─────────────────────────────────────────────────────┤
│  Access Token（短期）     Refresh Token（长期）       │
│  有效期：30 分钟           有效期：7 天               │
│  用途：接口认证            用途：刷新 Access Token     │
│  存储：内存（不持久化）     存储：MySQL token_refresh 表 │
│  无感：过期自动刷新         无感：7天后跳转登录         │
│  安全：短期泄露风险小        安全：服务端可撤销（强制登出） │
└─────────────────────────────────────────────────────┘

登录响应：
{
    "accessToken": "eyJ...（30min有效）",
    "refreshToken": "eyJ...（7day有效）",
    "expiresIn": 1800
}

**JWT Payload 扩展（含 ABAC 属性）**：

```json
{
    "sub": "zhangsan",
    "userId": 1,
    "role": "user",
    "department": "HR",                    // ★ ABAC: 所属部门
    "clearanceLevel": 2,                    // ★ ABAC: 数据密级
    "allowedDomains": ["HR", "FINANCE"],    // ★ ABAC: 可访问业务域
    "title": "manager",                     // ★ ABAC: 职级
    "iat": 1717401600,
    "exp": 1717484700
}
```

刷新流程：
  前端拦截器 401 → POST /api/auth/refresh { refreshToken }
  → 服务端验证 Refresh Token 有效性 + 未被撤销
  → 签发新 Access Token + 可选轮换 Refresh Token
  → 前端无感知更新 Token

强制登出：
  管理员 DELETE /api/auth/revoke { refreshToken }
  → 从 token_refresh 表删除 / 标记为 revoked
  → 该用户的 Refresh Token 立即失效
```

## 9. 关键设计决策

| 编号 | 决策项 | 决策 | 理由 |
|------|--------|------|------|
| D-001 | LLM Provider 抽象 | 策略模式，接口隔离 | 内部测试用 DeepSeek API，正式部署切换 Ollama，零代码改动 |
| D-002 | Embedding Provider 独立抽象 | 与 LLM 分离为独立接口 | 可能 LLM 和 Embedding 使用不同提供商 |
| D-003 | 文档处理异步化 | Spring Events + @Async | 文档解析/切片/向量化耗时长，异步不阻塞用户 |
| D-004 | 命令查询分离 | CQRS 模式 | 写操作为主的事件驱动 + 读操作直接查询，职责清晰 |
| D-005 | 向量库选型 | ChromaDB | 轻量级、无需独立部署集群、与 LangChain4j 集成好 |
| D-006 | 前端状态管理 | Pinia | Vue3 官方推荐，相比 Vuex 更轻量、TypeScript 友好 |
| D-007 | API 文档 | Knife4j (Swagger) | 自动生成，开发调试方便 |
| D-008 | 密码加密算法 | BCrypt（strength=12） | 自适应哈希，内置加盐，抗 GPU 暴力破解，替代不安全的 MD5 |
| D-009 | 检索策略 | 混合检索 + Rerank | 语义检索 + BM25 关键词双路召回，bge-reranker 精排，解决企业术语召回率低的问题 |
| D-010 | 流式响应 | SSE（Server-Sent Events） | 单向推送，实现简单，浏览器原生支持，相比 WebSocket 更轻量，首字节 ≤ 2 秒 |
| D-011 | 异步失败处理 | DLQ + 指数退避重试 | 死信队列保证失败事件不丢失，指数退避避免雪崩，4 次重试后转人工 |
| D-012 | LLM 容错 | 熔断器模式 | Ollama 连续失败自动降级到 DeepSeek API，保证问答服务高可用 |
| D-013 | 数据一致性 | 补偿模式（先标记后清理） | 文档删除异步执行，定时扫描孤儿向量，保证 MySQL 与 ChromaDB 最终一致 |
| D-014 | 文档解析增强 | PDFBox + POI + Tika + OCR | 表格转 Markdown 保留结构，Tesseract OCR 识别扫描件，提升切片语义完整性 |
| D-015 | 质量闭环 | 答案反馈评价（点赞/点踩） | 收集用户满意度数据，支撑 Prompt 优化和模型微调决策 |
| D-016 | 多源接入策略 | Connector 策略模式 | JDBC / REST / S3 三种连接器统一接口，新增数据源类型零改动核心逻辑 |
| D-017 | 数据质检 | 规则链（Chain of Rules） | 完整性→唯一性→格式→编码→长度顺序执行，合格率<50%自动阻断整批 |
| D-018 | 异构数据标准化 | ETL + 结构化→自然语言转换 | 字段映射引擎统一不同系统字段名和枚举值，DB表行/CSV行转为语义完整的自然语言段落 |
| D-019 | 知识目录路由 | 业务域三级目录 + 检索域裁剪 | 用户提问先匹配业务域，检索时只在该域范围内搜索，解决全库盲搜的精度和噪声问题 |
| D-020 | 增量同步 | CDC + 游标 + lastModified | JDBC 用时间戳游标，REST 用分页游标，S3 用文件修改时间，避免每次全量拉取 |
| D-021 | 结构化精确过滤 | MySQL B+树前置过滤 + ChromaDB ID 检索 | 结构化条件由 MySQL 索引承担，ChromaDB 仅在候选集内做语义检索，50 万切片延迟 ≤ 100ms |
| D-022 | 批量向量化 | BlockingQueue 攒批（32条/批）+ 多消费者 | 50 万切片向量化从逐条 27 小时压缩至 16 分钟（100 倍提升） |
| D-023 | 文档删除一致性 | MySQL 逻辑删除 + ChromaDB 物理 DELETE + 重试 | 脏读窗口 0 秒，补偿任务从"修复脏数据"降级为"重试失败删除" |
| D-024 | CQRS 读写分离 | 保留分离 + `@Transactional(readOnly)` 强制 + 路由 | 读走从库/无锁，写走主库，后期加只读副本零代码改动 |
| D-025 | OCR 策略 | AUTO 模式（自动检测文本密度） | 默认 `AUTO`：扫描件自动触发 OCR，正常 PDF 跳过，启动检测 Tesseract 可用性 |
| D-026 | PDF 解析 | 流式逐页 + 内存阈值保护 | 超大文件走流式解析，内存阈值默认 256MB，防止 OOM |
| D-027 | Embedding 维度兼容 | Collection 命名含模型标识 + 启动检测 | 切换 Provider 自动使用新 Collection，启动时检测维度一致性并提示 |
| D-028 | BM25 索引 | Lucene 磁盘索引 + 异步构建 + 增量更新 | 解决内存索引 50 万条 OOM 和启动阻塞问题 |
| D-029 | 全链路追踪 | MDC TraceId + TaskDecorator | 异步线程自动继承 TraceId，日志格式含 `[traceId]` |
| D-030 | JWT 认证 | 双 Token（Access 30min + Refresh 7day） | 支持静默刷新和强制登出 |
| D-031 | 凭据加密 | Jasypt + 环境变量密钥 | 数据源连接凭据加密存储，密钥不落盘 |
| D-032 | SSE 容错 | 断线重连 + token 偏移续传 + MySQL 回退 | 网络抖动自动恢复，3 次重试失败后从 MySQL 加载完整回答 |
| D-033 | 知识目录路由 | Embedding 语义路由替代关键词匹配 | domain 描述向量与 query 向量做余弦相似度，解决"这个月的绩效"等隐式查询的路由失效问题 |
| D-034 | 线程池隔离 | 解析/切片/向量化三池独立 | IO 密集型（向量化 8-20 线程）和 CPU 密集型（解析/切片）分离，互不阻塞 |
| D-035 | LLM 缓存 | Caffeine 本地缓存 | 相同问题（query+context 哈希）秒回，降低 LLM 调用成本和延迟 |
| D-036 | 访问控制模型 | ABAC（基于属性的访问控制） | 综合用户属性（部门/密级/职级/域）和资源属性（域/密级）动态计算权限，替代固定角色判断 |
| D-037 | ABAC 实施方式 | Spring Security SpEL + @PreAuthorize | 零外部依赖，策略集中在 AbacEvaluator 一个类中，可读性强，延迟 < 1ms |
| D-038 | 最小权限 | 默认用户仅访问本部门域 + 密级 1 及以下 | 防止越权读取跨部门数据和高密级文档 |
| D-039 | JWT 属性携带 | ABAC 属性编码到 JWT Payload | 避免每次请求查 MySQL，减少鉴权延迟 |
